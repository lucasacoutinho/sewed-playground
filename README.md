# Sewed playground

A small Electron playground for Sewed's execution and lifetime boundaries. It lives outside the library repository and consumes the packed public package.

Start with [the feature guide](FEATURES.md) for the feature index, then open the linked
record under [`docs/features`](docs/features) for behavior and verification details.
[Architecture](ARCHITECTURE.md) explains entry points, runtime ownership, component
lifetimes, and enforced boundaries.
[Verification](docs/verification.md) covers the test workflow and evidence.

Native ownership and RPC come from `sewed`; React mounting and hooks come from `@sewed/react`. The separate `@sewed/vite` package owns the development build and restart loop. The optional `@sewed/devtools` package adds headless diagnostic snapshots and Effect tracing. All four are consumed as local packed artifacts.

For the minimum application wiring, start with [the library walkthrough](../sewed/docs/getting-started.md). `src/main/app.ts` chooses owners and bindings; `src/main/session.ts` contains the playground's status readouts and background instrumentation. That instrumentation is optional application code.

```sh
pnpm install
DISPLAY=:0 pnpm dev
DISPLAY=:0 pnpm dev:inspect
```

`dev` runs the local architecture and type checks, then starts Vite. Main, worker, and shared-contract edits compile into a fresh staging directory and restart Electron after successful compilation. A failed compilation preserves the running app; renderer edits use React Fast Refresh. Closing Vite or the final application window stops the development session. For the built application, use `DISPLAY=:0 pnpm start`.

The app opens two React windows bound to one compute worker. Compute has a clock worker dependency supplied by main. Each window receives its own native controls. The three colored lanes show where an operation executes; React draws the entire interface.

Before either window opens, main starts a compute stream through `Binding.layer`. Compute reads its declared `Clock` binding, and the clock worker supplies the timer ticks. The application-owned work readout shows both real thread IDs. Reloading a renderer or closing one window leaves that stream running. Closing the final window releases the application scope and both workers.

`dev:inspect` enables scoped diagnostics and Effect tracing while opening the same two React windows. Main acquires `DevTools.make()` in the application scope; its typed snapshot exposes owners, bindings, requests, resources, stream counters, spans and health. The package creates no UI or extra renderer bridge. Electron Chromium DevTools is available through the normal WebContents API.

## Source layout

```text
src/
  main/app.ts                 # App scope, native windows, workers, bindings
  main/session.ts             # Playground status, observers and background work
  worker/compute.ts           # CPU loop and interruptible handlers
  worker/clock.ts             # Bound timer stream in another worker
  shared/                     # Inert protocols and binding declarations
  renderer/
    main.tsx                  # StrictMode and RouterProvider
    router.ts                 # Typed TanStack Router with hash history
    routeTree.gen.ts           # Generated by the TanStack Vite plugin
    routes/
      __root.tsx              # Shared layout
      index.tsx               # Request lifetime
      scopes.tsx              # React resource scopes
      source.tsx              # Source boundaries
      renderers.tsx           # Native web contents lifecycle
      resources.tsx           # Worker-owned remote resource
    app/                      # Shell, providers and feature composition
    features/<name>/          # Collocated components and scoped hooks
    lib/sewed.tsx             # One renderer bootstrap adapter
```

The renderer follows [TanStack Router's Vite setup](https://tanstack.com/router/latest/docs/installation/with-vite). `Link` and `Outlet` replace manual tab state. Hash history works with the built `file://` entry, including back/forward navigation and reloading a route. The native window identity stays in the document query string, separate from the route hash.

Components and routes use ordinary React, with pure Effect helpers such as `Match` for presentation branches. Feature hooks own scoped clients, actions, and streams. `lib/sewed.tsx` attaches the renderer runtime at startup. React owns rendering and TanStack owns navigation. The root desktop context holds window-level work while route components own their local state and scopes.

Import rules and separate compiler configurations enforce the source structure. Effect requirements and runtime capabilities enforce placement; bindings dispatch calls to selected instances. Arbitrary JavaScript can still block a renderer. Sewed does not analyze the cost of a function.

`pnpm check` validates feature source ownership and record links, then rejects forbidden
imports, entry-file bypasses, effect hooks, comments, and type escapes in application
source. The
[feature index](FEATURES.md) links those boundaries to a focused feature record under
[`docs/features`](docs/features).

The renderer heartbeat is a scoped `Stream.tick`. Main and worker snapshots come from `SubscriptionRef` streams. The playground uses no React effect hooks to start timers or manage subscriptions.

To inspect automated evidence, use
`pnpm verify:features resources --report .artifacts/verification.json`. The
[verification guide](docs/verification.md) explains metadata lookup, current build
requirements, and partial coverage on failure.

## Experiments

- Watch application-owned work while reloading or closing a window. Main starts the stream once; Compute reads Clock through a worker binding. Both worker instances and the subscription survive renderer reloads.
- Run CPU work and click the renderer counter or maximize the window while it runs. The CPU loop occupies the worker for 1.2 seconds.
- Start a slow request, replace it, or cancel it. The live worker snapshot shows handler acquisition and release in both windows. The wait is interruptible; the synchronous CPU loop cannot be preempted by cancellation.
- Acquire a renderer lease in the React scopes route. Success retains it. Replacement, cancellation, failure, and component unmount release it.
- Open Remote data to acquire a worker-owned resource and stream 32 MiB through it. Cancel a transfer, reuse the resource, explicitly release it, or leave the route to close its `useResource` lifetime.
- Inspect the source boundaries route for excerpts showing declarations, owners, and clients.
- Open Renderer lifecycle to inspect the two native web contents states, renderer process IDs, and
  navigation failures and responsiveness. Another window can explicitly reload or recover a lost
  renderer while main retains its native window and worker bindings.
- Stop the shared compute worker. Pending calls fail, its clock subscription releases, and both windows disable compute operations. The clock owner and renderer/native controls remain alive. Reload preserves the stopped owner. Close the windows and run `pnpm start` to create a new session.

Reloading or closing a window releases its old document's connections. Closing the final window closes the application scope.

```sh
pnpm check

pnpm verify:binary

pnpm benchmark:transport
```

The CDP harness runs the built application by default and the actual Vite development launcher with `--dev`. It checks runtime boundaries, routing/history/reload, keyboard links, narrow layouts, and development Fast Refresh. The refresh probe temporarily edits a component and restores its exact contents; it refuses to overwrite a concurrent edit. Reports and screenshots are written under `.artifacts/`. Each run closes only its own process. Vite module metadata is checked for native and worker implementations.

`verify:native-views` checks the public BaseWindow and WebContentsView composition APIs with real native windows, separate renderer bindings, attachment scopes, and WebContents destruction. `verify:responsiveness` stalls a real visible renderer, waits for native unresponsive/responsive events, then recovers a second stall through the main-owned API. That fixture takes about 40 seconds because it uses Chromium's real hang detector.

`verify:resource-inspection` uses the built playground worker through public packages. It checks resource ownership, sampled binary wire counters, cancellation, cleanup, and the headless DevTools snapshot without creating a native window. The ordinary `verify` and `verify --dev` runs exercise the React resource hook in StrictMode, including replacement, 32 MiB transfers, and route cleanup.

### Terminal shutdown acceptance

```sh
pnpm verify:terminal
```

This command runs the real `pnpm run dev` and `pnpm run dev:inspect` launchers in sequence. It gives each run private XDG configuration, cache, data, state, and temporary directories, reserves separate loopback Vite and CDP ports, waits for exactly the two React windows in both modes, then sends SIGINT to the Vite CLI process group. The report records CDP process IDs, `/proc` ancestry, detached Electron groups, terminal exit, port closure, scope finalizer logs, and any teardown `No handler registered` errors under `.artifacts/terminal/`.

The command verifies Electron and renderer shutdown on the Linux side. This WSL environment has no Windows-side native-window harness, so the report records that limitation instead of claiming Windows native-window evidence.

Every CDP run crashes one renderer, observes its loss from the other window, and uses that window's bound main action to reload it. It checks that pending document requests release, workers keep running, and recovery preserves native window and worker identities while the renderer process changes.

`verify:webcontents` uses hidden Electron windows and a local HTTP fixture to check navigation, redirects, subframe errors, cancelled and superseded loads, process loss, and observer lifetimes. Native fault injection stays in that test fixture. It consumes the same packed public Sewed package as the React app.

`verify:dx` builds a separate React fixture in production and development modes and runs each in Electron through the packed packages. It checks stream dependency changes, rerenders, discarded Suspense renders, late results, failures, unmount, reload, and shutdown. It also checks binding diagnostics, missing preload, and rejected handshakes. The hidden fixture uses real React, IPC and main-host requests; native navigation to an unbound document is an explicit boundary check. Malformed IPC responses and an open rejection are labeled as injected checks. Its reports live in `.artifacts/dx-*-verification.json`.

`verify:development` creates a disposable consumer under `.artifacts/development` and exercises the public Vite plugin with Electron, a real Sewed worker, and React. It checks main/worker/shared edits, Fast Refresh state retention, failed-build recovery, serialized restarts, and process cleanup. It never edits the playground application's sources.

`verify:diagnostics` checks exact renderer binding targets and Effect client span ownership, document reload, renderer crash, request cleanup, and final scope closure through the public diagnostics collector. Its report lives in `.artifacts/diagnostics-verification.json`.

`verify:app` checks scoped activation observers, explicit window reopening, and application shutdown with asynchronous finalizers. Activation is a macOS Electron event; the Linux fixture injects it at Electron's event boundary and verifies real window ownership and process exit. It does not verify macOS Dock delivery.

`verify:windows` checks native visibility, focus, bounds, fullscreen, state replay, input validation, and explicitly bound controls for two distinct window owners. It uses Electron's X11 backend for positioning, focus, and `showInactive` checks. Geometry snapshots include actual and normal bounds, with real fullscreen and maximize/restore transitions. Hiding preserves the renderer document and bound owner; closing the owner invalidates its clients. Native verification scripts share one process launcher with bounded execution and retained failure reports.

`verify:screen` compares display discovery, cursor coordinates, and display selection with real Electron queries on X11. It injects display notifications to verify event payloads, subscription isolation, queue overflow, cleanup, and explicitly hosted bindings. It does not simulate changes to the operating system display configuration or prove physical hotplug delivery.

`verify:surfaces` checks the theme, power, notification, clipboard, shell, and safe storage capabilities through the packed public package: theme state replay and a read-only host, power event registration, one notification's scoped lifetime, clipboard round trips and a host's format policy, and a redacted secret sealed and reopened. The shell checks cover origin, document, and `mailto` rules denying URLs and paths outside their policy, and a match-pattern policy (`*://*/*` for every http or https URL): `openExternal` refuses a URL carrying credentials whatever the rule, refuses a `javascript:` URL the pattern's scheme excludes, and a policy naming `<all_urls>` or a `file:` pattern fails while the Layer builds — `file` is not a pattern scheme, since a pattern's path is matched against the URL as written and a percent-encoded separator would reach it undecoded. It does not call `openExternal` with a URL the policy allows, so it never asks the OS to open a real browser; that allowed case is covered by the unit suite against `ShellPolicy.operations`.

`verify:dialogs` builds a separate renderer fixture and checks native message boxes on Linux/X11. A Python helper identifies the fixture process's visible dialog by title and checks its native parent before Return/Escape input. It uses the system `libX11` and `libXtst` libraries. The checks cover real button responses, checkbox state, request interruption, parent and host closure, option validation, exclusive presentation, and renderer cancellation/reload through public bindings. Reports distinguish native interaction from injected error paths.

`verify:file-dialogs` exercises file, directory, multi-file, and save-path selection through the packed library. It forces Electron's GTK/X11 backend with English labels for keyboard verification. Request cancellation and parent closure are checked separately from native dismissal: file pickers can remain open, competing dialogs fail with `Limit`, and late results cannot reach an interrupted request or a reloaded document. The fixture uses disposable files, verifies their contents remain unchanged, and keeps its renderer protocol outside the React application. Native throws, malformed responses, and delayed promise settlement are identified as injected checks.

`verify:sessions` loads loopback origins in windows with shared and separate browser sessions. It checks cookies, HTTP cookie headers, local storage, default-session behavior, case-sensitive names, scope/window closure, renderer reload, and explicit bindings to a shared worker. It also checks browser permission denial, grants and revocation, subframe denial, selected storage clearing, popup blocking, navigation rules, redirects, and explicit rebinding after navigation. Three sequential Electron processes use temporary profiles: the first checks native behavior, and the next two check that persistent data survives normal quit and restart while memory data does not. Forged handles, malformed native permission metadata and native failures are identified as injected checks. The fixture lives in `scripts/session-renderer` and consumes the packed public package.

`benchmark:transport` runs an isolated renderer and two real worker threads through the packed library. It measures main-to-worker and renderer-to-worker paths, directly and through a worker dependency, with 1, 64 and 192 KiB payloads. Each size has five warmups, 40 unary round trips and 32 responses produced as a batch. It verifies payloads and owner thread IDs, checks oversized values and stream cancellation, and records maximum main event-loop timer delay. Results, workload profile and runtime versions are saved to `.artifacts/transport-benchmark.json`. This is a local measurement, not a capacity guarantee; rates count response payload bytes and exclude RPC envelope overhead. The benchmark code stays in `scripts/transport-*`, outside the React application and the library.

Sewed splits batches to fit the byte limit, including when a forwarding stream regroups values. The benchmark has no manual `rechunk` workaround. It also sends escaped Unicode and proves that oversized requests and individual responses fail while an unrelated concurrent request and later calls use the same client and worker owners. Batched-stream results should not be compared directly with the earlier one-value-per-chunk workload.

`verify:menus` checks native context menus on Linux/X11 through the packed public API. The X11 helper identifies the fixture's menu windows by process and native window type, then focuses the selected fixture parent and verifies that focus before sending each key. Checks cover command and checkbox results, nested radio menus, dismissal, exclusive presentation, parent and request lifetimes, option validation, and bound renderer cancellation/reload. Dialog and menu fixtures share the Python X11 bindings and require `libX11` and `libXtst`. Run native fixtures sequentially because they use the same desktop.

`verify:application-menus` checks the application menu `App.menu` acquires and its handle's `selections` observers. It drives real menu-bar navigation, shortcuts, checkboxes, radio items, native editing roles, and window closure. It verifies renderer forwarding and reload, observer cancellation/failure/overflow, survival without windows, a second live menu, and shutdown with a submenu open. Separate Electron processes verify an application that never acquires a menu and startup rejection for invalid options or injected native failures. The JSON report distinguishes those injected failures from native keyboard checks. The renderer fixture lives in `scripts/application-menu-renderer`; the React application remains an ordinary consumer.

For unattended native verification, use an isolated display, for example `python3 scripts/with-xvfb.py dbus-run-session -- pnpm verify`. The wrapper requires `Xvfb`, Openbox, and `xprop`; `pnpm ui-tools` builds both from their packages without root and prints the `SEWED_XVFB` and `SEWED_WINDOW_MANAGER` exports that select them, and `pnpm verify:all` runs every fixture in one display session. It starts a temporary authenticated X display and window manager, verifies EWMH readiness, and cleans up its own processes. This supports real maximize/restore checks and avoids desktop focus changes during keyboard input. A private D-Bus session keeps the native fixture's services separate. Run native fixtures sequentially.

The `--lifetime` run keeps both workers alive until application shutdown. It verifies that closing one window preserves the main-owned stream, then checks both stream release events when the final window closes. The normal run terminates Compute and verifies its downstream subscription releases while Clock stays alive. All runs check the distinct thread IDs, subscription continuity through reload, and final clock owner cleanup.

All protocols, workloads, diagnostics, and UI in this directory are playground code. The sibling library remains independently packaged. The locally bundled Manrope fonts use the SIL Open Font License in `src/renderer/public/Manrope-OFL.txt`.

The desktop foundations fixtures consume only packed public APIs:

- `pnpm verify:lifecycle`: two real Electron processes proving `App.claimInstance` — the secondary runs its own checks, fails its claim once its arguments are forwarded, and quits with code 0, while the primary receives the forwarded launch on `instance.launches` — plus early launch queue adapters, asynchronous close/quit guards, and shutdown finalizers. Linux checks inject macOS-only file/URL events; OS launch delivery on macOS remains a separate platform check.
- `pnpm verify:desktop`: a task-owned StatusNotifier/DBusMenu host and XTest keyboard input for native trays, menu selections, global shortcuts, scoped cleanup, and explicit renderer bindings. The report identifies platform-dependent tray gestures.
- `pnpm verify:utility`: distinct Electron utility PIDs, typed RPC and dependencies, cancellation, renderer reload, crashes, startup failure, and graceful/forced teardown.
- `pnpm verify:devtools`: headless snapshots, cross-runtime trace correlation, worker placement, cancellation, reload, native Chromium DevTools, bounded history, and scoped cleanup.
- `pnpm verify:devtools-development`: the optional Vite wrapper through actual development generations, including compilation failures and shutdown.
- `pnpm verify:remote`: isolated resource state, acknowledged delayed finalizers, stalled consumers, renderer reload, owner loss, and a worker acquiring a downstream utility resource.
- `pnpm verify:binary`: typed bytes and errors, 16 MiB streams, slow consumers, cancellation, and reuse across main, worker, utility, and relay routes; renderer to main, a 12 MiB `Binary.bulk` attachment ingest at exactly its declared bound, and one byte over failing `Limit` before anything is sent. Memory and throughput observations describe the local run.
- `pnpm verify:session-resources`: `Protocol.declare` registration and session-owned protocol responses and request cleanup, independent same-URL downloads, native progress, pause/resume/cancel, file hashes, and scoped teardown.

The headless snapshot joins RPC client/server spans across runtime boundaries. Its health records report timer lateness, actual Sewed queue sizes, and active request counts. These observations do not measure CPU utilization or Electron's hidden native queues.

Use the isolated X11/Openbox/private D-Bus wrapper above for these native checks. Their support programs stay under `scripts/`, separate from the React/TanStack application.
