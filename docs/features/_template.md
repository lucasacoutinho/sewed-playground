# Feature name

Use one record for one user-facing behavior. Keep the explanation about ownership and
lifetime; link to implementation instead of duplicating it.

## Behavior

Describe what a person can observe and the scenarios that matter.

## Ownership

Name the runtime owner and the boundary where the work executes.

## Lifetime

State what keeps the work alive and what releases it.

## Contracts and dependencies

Link the shared protocol, binding, or adapter that crosses the boundary.

## Source

Link the entry points and the feature components that implement the behavior.

## Verification

Name the metadata entry, scenario IDs, and the static or Electron commands that exercise
the behavior.

## Limits

State what the playground or its fixtures do not prove.
